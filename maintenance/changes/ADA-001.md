# ADA-001 Adaptive Maintenance

## Change

Support the local lab runtime and Apple Silicon JavaFX.

Status: implemented and verified within the stated scope.

Initiating condition: The baseline targets Java 25, while the selected local lab runtime is JDK 21 on macOS ARM64. The baseline build genuinely fails with invalid source release 25. The JavaFX configuration also declares generic mac, win and linux classifiers together rather than selecting the host architecture. Java 21 was an implementation-selected compatibility target, not an instructor requirement. Reusing the selected local JDK and explicitly selecting host-native JavaFX artifacts is the scoped environment adaptation. Installing/selecting JDK 25 while retaining the original target was a valid alternative; no claim is made that this was impossible or inferior. The compiler failure and the separately inspected native-dependency gap are distinct findings.

## 1 Program comprehension

Inspect build.gradle, Gradle wrapper, installed JDKs, source language features and JavaFX native dependencies. Gradle orchestrates compilation/tests; its launcher JVM and the Java toolchain can differ. Native JavaFX binaries must match the runtime OS and CPU.

## 2 Change management

Acceptance criteria and scope: Use the Java 21 toolchain for compile/test; select mac-aarch64 on this host; preserve existing application behavior and test success; package and launch the desktop app. Domain objects and persisted JSON formats must stay compatible.

Implementation commit: ddedfbc2. Original baseline remains tagged. No upstream publication or PR is claimed.

Rollback: use the original snapshot or review the relevant patch in a separate checkout. Restoring the original Java 25 target on a JDK 21 compiler restores the known build mismatch. Do not overwrite user data as part of rollback.

## 3 Impact analysis

| Surface | Risk | Control |
|---|---|---|
| Java compiler | Source uses unsupported language features | Full compile with Java 21 |
| Test JVM | Confuse Gradle launcher and application toolchain | Declared toolchain and fresh test log |
| JavaFX natives | Architecture mismatch at launch | Host classifier selection and actual ARM64 UI smoke |
| Other hosts | Unverified platform selection | Do not claim Windows/Linux verification |

Recovered build flow: Gradle wrapper -> JDK 21 toolchain -> source/test tasks; host OS/arch -> four JavaFX modules -> desktop runtime. OpenJDK 27 was installed with PMD and also launched a fresh Gradle test/style run. That verifies Gradle-launcher compatibility while the application toolchain remains 21.

## 4 Reverse engineering

The build and native dependency flows above were recovered manually from the Gradle configuration and verified against its tasks/logs. They are not an automatically extracted CPG or a Doxygen-generated Gradle graph. Java documentation and the separate parser AST belong to other project evidence.

## 5 Refactoring

Replaced twelve repeated per-platform JavaFX dependency declarations with a four-module loop and one classifier selection. Centralizing the selection reduces independent configuration edits.

## Verification

After: 01-adaptive-tests.txt shows successful regression build; 16-jdk27-fresh.txt records fresh tasks launched by OpenJDK 27; native UI smoke and jpackage output support this Mac only. Lowering a target is an explicit local compatibility choice, not an external requirement or an inherently superior alternative to using JDK 25.

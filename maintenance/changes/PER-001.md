# PER-001 Perfective Maintenance

## Change

Find contacts by existing tags.

Status: implemented and verified within the stated scope.

Initiating condition: The baseline can store and display tags, but its find command filters only name words. The enhancement lets a user retrieve a group using existing tag data without altering contacts. This is a usability/functionality improvement, not an environmental adaptation.

## 1 Program comprehension

Trace AddressBookParser -> FindCommandParser -> NameContainsKeywordsPredicate -> FindCommand.execute -> ModelManager.updateFilteredPersonList -> JavaFX observable list. Identify the concrete predicate dependency that prevents reuse for another match policy.

## 2 Change management

Acceptance criteria and scope: Support find t/TAG [MORE_TAGS]... with OR semantics and exact whole-tag case-insensitive matches. Reject empty tag queries. Preserve normal name search and list restoration. Filtering must not mutate contact data. The t/ mode reserves that leading syntax; repeated t/ prefixes and mixed name/tag expressions are not introduced.

Implementation commit: 7268979e plus documented help-text refinement. Original baseline remains tagged. No upstream publication or PR is claimed.

Rollback: use the original snapshot or review the relevant patch in a separate checkout. Reverting the adaptive build on a JDK 21 machine restores its known build failure; reverting atomic writes restores the original truncation risk. Do not overwrite user data as part of rollback.

## 3 Impact analysis

| Surface | Risk | Control |
|---|---|---|
| Parser | Empty or ambiguous tag query | Explicit t/ mode and empty-query regression |
| Existing find | Name matching changes | Existing tests and integration check |
| Model/UI | Hidden contacts mistaken for deletion | Underlying list count and list restoration check |
| Storage | Unnecessary schema change | No new contact fields or JSON format |

Recovered architecture: diagrams/architecture.dot and PNG. Parser syntax tree: evidence/12-find-parser-ast.txt. UI screenshots show actual sample-data filtering, usage error, and restored listing.

## 4 Reverse engineering

The recovered relationships and flow above were checked against current source and cross-referenced with generated documentation. Diagram sources are editable Graphviz files under maintenance/diagrams. Tool-generated AST/documentation and manually reconstructed behavior diagrams are distinguished.

## 5 Refactoring

Generalized FindCommand's field/constructor from NameContainsKeywordsPredicate to Predicate<Person>. The command keeps one execution/count path. A separate immutable-list TagContainsKeywordsPredicate supplies tag matching. Existing name predicate behavior remains covered.

## Verification

TagSearchIntegrationTest crosses the production command parser, command, predicates and filtered model. It checks case-insensitive OR search, whole-tag behavior, list restoration, name search and preservation of stored contact count; the second test rejects an empty tag query. Native desktop smoke showed Alex Yeoh and Bernice Yu for find t/FRIENDS. See screenshots and final regression results.

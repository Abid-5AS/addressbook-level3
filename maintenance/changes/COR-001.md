# COR-001 Corrective Maintenance

## Change

Saved JSON null must use normal recovery.

Status: implemented and verified within the stated scope.

Initiating condition: A file containing the four characters `null` is valid JSON. Jackson returns Java null. The original readJsonFile then calls Optional.of(null), which throws NullPointerException outside the catch for IOException. MainApp catches DataLoadingException, so this malformed saved application document bypasses its ordinary recovery path. The new regression first failed with the unexpected exception. This is a reproduced defect in an existing contract, not a deliberately introduced defect.

## 1 Program comprehension

Trace MainApp.initModelManager/initPrefs -> JsonAddressBookStorage/JsonUserPrefsStorage -> JsonUtil.readJsonFile -> Jackson decoder. Contacts and preferences share this utility. Read the try/catch boundary and the Optional constructor; the decoder's valid-JSON result can still be unusable application data.

## 2 Change management

Acceptance criteria and scope: Accept JSON objects as before; keep absent-file Optional.empty behavior; reject a top-level null document through DataLoadingException; preserve valid serialization and all existing storage tests. The source scope is JsonUtil plus its regression test. The helper extraction does not change the corrected behavior.

Implementation commit: 7110f09a; refactoring c0060abb. Original baseline remains tagged. No upstream publication or PR is claimed.

Rollback: use the original snapshot or review the relevant patch in a separate checkout. Reverting the adaptive build on a JDK 21 machine restores its known build failure; reverting atomic writes restores the original truncation risk. Do not overwrite user data as part of rollback.

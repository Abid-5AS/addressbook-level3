# PRE-001 Preventive Maintenance

## Change

Stage JSON saves before replacing live data.

Status: implemented and verified within the stated scope.

Initiating condition: The original save serializes JSON and writes bytes directly to the target file. A write interrupted after truncation can leave partial saved data. No historical user data-loss incident is claimed. This case reduces a known future failure mode before relying on such an incident.

## 1 Program comprehension

Trace LogicManager save calls through storage adapters into JsonUtil.serializeObjectToJsonFile and FileUtil.writeToFile. Identify the boundary where the live target can change before all new content has been staged.

## 2 Change management

Acceptance criteria and scope: Complete serialization before disk replacement. Write UTF-8 to a sibling temporary file, replace with ATOMIC_MOVE, and clean staging files. If staging fails, preserve existing bytes. If atomic move is unsupported, fail rather than silently write non-atomically. Test replacement, nested parent/UTF-8, and injected interrupted staging.

Implementation commit: dd9d211b. Original baseline remains tagged. No upstream publication or PR is claimed.

Rollback: use the original snapshot or review the relevant patch in a separate checkout. Reverting the adaptive build on a JDK 21 machine restores its known build failure; reverting atomic writes restores the original truncation risk. Do not overwrite user data as part of rollback.

## 3 Impact analysis

| Surface | Risk | Control |
|---|---|---|
| Contacts/preferences | Shared save behavior changes | Existing JSON/storage tests |
| Disk space | Staging needs temporary additional space | IOException reaches existing caller handling |
| Filesystem | Atomic replacement may be unsupported | Explicit failure; no non-atomic fallback |
| Permissions/symlinks | Replacing an inode differs from writing through it | Local regular-file scope; no preservation guarantee claimed |
| Power loss | Atomic visibility is not full durability | No fsync or backup guarantee claimed |

Recovered flow: diagrams/save-flow.dot and PNG. The deterministic failure occurs after partial temporary-file output; it is not an actual power-cut experiment. On a first save, storage may create an empty target before serialization; preserving an existing valid file is the guarantee tested here.

## 4 Reverse engineering

The recovered relationships and flow above were checked against current source and cross-referenced with generated documentation. Diagram sources are editable Graphviz files under maintenance/diagrams. Tool-generated AST/documentation and manually reconstructed behavior diagrams are distinguished.

## 5 Refactoring

Centralized staging/replacement/cleanup in FileUtil.writeAtomically; JsonUtil delegates. A package-private ContentWriter seam injects a partial-write IOException without relying on nondeterministic disk failures. Other FileUtil.writeToFile callers retain their prior behavior.

## Verification

AtomicFileWriteTest has three cases: complete replacement and cleanup; injected partial staging with original preservation and cleanup; nested parent creation with UTF-8. Existing JsonUtil and storage tests also pass. See 06-preventive-tests.txt and final full-suite evidence.
